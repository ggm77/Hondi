# 혼디 가게

> 제주도 여행, 택시비도 같이 나눠요

'혼디'는 제주말로 '함께'라는 뜻이에요.
혼디 가게는 **동선이 비슷한 제주 여행객끼리 택시를 함께 탈 사람을 미리 모아주는** 동승 매칭 서비스입니다.

🔗 **서비스 주소: [hondi.seohamin.com](https://hondi.seohamin.com)**

<br>

## 왜 만들었나요

렌터카 없이 떠난 제주 여행에서는 택시비가 가장 부담이에요.

| | 문제 |
| --- | --- |
| 01 | **버스로는 닿지 않는 곳이 많아요.** 노선이 원도심과 주요 관광지 위주라 오름이나 해안 마을은 가기 어려워요. |
| 02 | **렌터카는 부담스러워요.** 혼자 여행하면 대여비와 운전 부담을 혼자 다 져야 해요. |
| 03 | **같이 탈 사람을 찾을 곳이 없어요.** 오픈채팅이나 SNS에 올라온 '택시 같이 타실 분' 글은 흩어져 있고 믿기 어려워요. |

혼디 가게는 이 과정을 세 단계로 줄였어요.

1. **모집글을 올려요.** 출발지, 목적지, 희망 시간, 인원만 적으면 돼요.
2. **동선이 겹치는 사람을 찾아요.** 경로와 시간대가 비슷한 모집글을 자동으로 추천해요.
3. **채팅으로 만날 곳을 정해요.** 택시 호출과 요금 나누기는 만나서 직접 해요.

### 이용 시나리오: A씨의 제주 첫날

| 시각 | 상황 |
| --- | --- |
| 14:20 | 제주공항에 도착해서 '공항 → 애월 숙소, 15시' 모집글을 올려요. |
| 14:35 | 비슷한 동선과 시간대의 B씨가 추천 목록에서 보고 합류해요. |
| 14:45 | 채팅으로 '3번 게이트 앞 택시승강장'에서 만나기로 해요. |
| 15:00 | 함께 택시를 타고 출발하고, 요금은 도착해서 반씩 내요. |

> 혼디 가게가 하는 일은 매칭까지예요. 승차와 요금 분담은 현장에서 직접 해요.

## 주요 기능

| 기능 | 설명 |
| --- | --- |
| **동선 검색** | 출발지, 목적지, 시간을 입력해 동승 상대를 찾아요. |
| **추천 동승** | 출발지 3km, 목적지 5km, 출발 시간 ±1시간 안의 모집글만 골라서 출발 시간이 가까운 순으로 보여줘요. |
| **지도 탐색** | 모집 중인 글을 지도 위에서 한눈에 봐요. |
| **지도에서 장소 선택** | 주요 장소 25곳 목록에 없는 오름이나 해안 마을도 지도에서 바로 찍어요. 주요 장소 0.7km 안이면 'OO 부근'으로, 아니면 OpenStreetMap 주소로 이름을 자동으로 붙여요. 바다나 제주 밖을 찍으면 다시 고르도록 안내해요. |
| **그룹 채팅** | 모집글 하나가 채팅방 하나예요. 방장과 참여자만 메시지를 보고 보낼 수 있어요. |
| **읽음 표시** | 읽은 메시지에는 '읽음'을, 채팅방 목록에는 안 읽은 메시지 수를 보여줘요. |
| **빠른 답장** | '어디서 만날까요?' 같은 말을 버튼 한 번으로 보내요. |
| **카카오 로그인** | 카카오 계정으로 로그인하면 닉네임으로 바로 가입돼요. |

## 핵심 설계

### 1. 동선 매칭

매칭은 두 단계로 걸러요.

1. **DB 1차 필터:** 출발지 기준 바운딩 박스와 출발 시간 범위(±60분)로 후보를 좁혀요. 정원이 찬 글과 이미 참여한 글은 빼요.
2. **하버사인 2차 필터:** 출발지 3km, 목적지 5km 이내인지 실제 거리를 계산하고, 출발 시간이 가까운 순으로 정렬해요.

처음에는 가중치 점수로 매칭했지만, 사용자가 결과를 이해하기 쉽도록 **조건 필터 + 출발 시간 가까운 순**으로 단순화했어요.

→ `RideMatcher`, `RideListService.matchRides`

### 2. 채팅: WebSocket 대신 1초 HTTP 폴링

WebSocket 없이 HTTP 폴링과 메시지 ID 커서로 그룹 채팅을 만들었어요.

```
 895   896   897 │ 898   899   900   901 │ 902   903   904
 ───────────────   ─────────────────────   ───────────────
 위로 스크롤하면     화면에 보이는 메시지     1초마다 afterId
 beforeId로 50개씩   (입장 시 최근 50개)      이후만 받아서 붙이기
```

1. **입장:** 최근 50개를 불러오고 마지막 ID를 `afterId`로 기억해요.
2. **폴링:** 새 메시지를 ID 기준으로 합치고, 더 있으면(`hasNext`) 이어서 요청해요.
3. **읽음 처리:** 마지막으로 본 ID를 저장해 '읽음' 표시와 안 읽은 개수에 써요.

**폴링을 고른 이유**

- **서버 구성이 단순해요.** 기존 REST API를 그대로 쓰고 연결 상태를 따로 관리하지 않아요.
- **대화에는 1초 간격이면 충분해요.** 만날 곳을 정하는 대화라서 밀리초 단위의 실시간성은 필요 없어요.
- **끊겨도 알아서 이어져요.** 일시적인 오류는 다음 폴링에서 다시 시도해요.

**놓치지 않게 챙긴 것**

- **메시지 누락 방지:** 같은 방의 메시지 전송은 모집글 행 잠금으로 직렬화해요. 앞선 메시지가 커밋된 뒤에 다음 ID가 발급되니까 `afterId` 폴링에서 건너뛰는 메시지가 없어요.
- **커서는 폴링으로만 이동:** 내가 보낸 메시지로 `afterId`를 올리면 그 사이에 온 남의 메시지를 건너뛸 수 있어서, 커서는 폴링 응답으로만 옮겨요.
- **입력 중인 글자 보호:** 새 메시지가 와도 메시지 영역만 다시 그려서 한글 조합이 깨지지 않아요.
- **멤버만 대화:** 참여를 취소하거나 글이 삭제되면 채팅방에서 자동으로 나가요.

### 3. 동시 참여 처리

마지막 한 자리에 여러 명이 동시에 참여해도 정원을 넘지 않도록 세 겹으로 막아요.

| 단계 | 방법 |
| --- | --- |
| 모집글 잠금 | `SELECT ... FOR UPDATE`로 참여, 탈퇴, 수정(정원 변경)을 직렬화 |
| 원자적 갱신 | `UPDATE ... SET current_count = current_count + 1 WHERE current_count < capacity`, 영향받은 행이 0이면 정원 초과 |
| 유니크 제약 | `(ride_id, user_id)` 유니크 제약으로 중복 참여를 DB에서 차단 |

→ `RideParticipantService`, `RideConcurrencyTest`, `RideWriteConcurrencyTest`

## 실행 방법

### 백엔드

필요한 것: Java 25, MariaDB

`backend/src/main/resources/application.yml`은 저장소에 포함되지 않아요. 아래 형식으로 직접 만들어 주세요.

```yaml
spring:
  application:
    name: hondi
  jpa:
    open-in-view: false
    hibernate:
      ddl-auto: update
  datasource:
    url: jdbc:mariadb://localhost:3306/hondi
    driver-class-name: org.mariadb.jdbc.Driver
    username: <DB 사용자>
    password: <DB 비밀번호>

server:
  port: 52727

springdoc:
  swagger-ui:
    path: /api/swagger
  api-docs:
    path: /api/swagger-ui/v3/api-docs

jwt:
  secret: <Base64 인코딩된 256bit 이상 키 (openssl rand -base64 32)>
  access-token:
    expr-time: 3600
  refresh-token:
    expr-time: 1209600

cors:
  allowed-origins: http://localhost:5173
```

```bash
cd backend
./gradlew bootRun
```

- Swagger: `http://localhost:52727/api/swagger`
- 테스트: `./gradlew test` (H2 사용, `src/test/resources/application.yml` 필요)

### 프론트엔드

빌드 없이 정적 파일을 그대로 띄우면 돼요.

1. `frontend/js/config.js`에서 `API_BASE_URL`을 백엔드 주소로 바꿔요. (로컬이면 `http://localhost:52727`)
2. 카카오 디벨로퍼스에 JavaScript 키와 Redirect URI(프론트 주소)를 등록하고, `KAKAO_CLIENT_ID`에 JavaScript 키를 넣어요.
3. 정적 서버로 실행해요. 백엔드 CORS 설정과 포트를 맞춰 주세요.

```bash
cd frontend
npx serve -l 5173
```
